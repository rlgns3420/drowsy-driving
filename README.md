# Python 졸음운전 감지 시스템

Python 3.11, OpenCV, MediaPipe Face Mesh와 웹캠을 사용합니다. PC용 전체 실행 흐름을 구현했으며, 카메라·연산 해상도·시간 기준을 설정으로 분리해 Raspberry Pi로 옮길 수 있게 구성했습니다. 영상 저장, 서버, 별도 UI 프레임워크는 사용하지 않습니다.

## PC 실행

현재 작업 폴더에는 의존성을 설치한 `.venv`가 있습니다. PowerShell에서 실행합니다.

```powershell
cd D:\졸작
.\.venv\Scripts\python.exe main.py
```

다른 PC에서 설치할 때:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

1. 웹캠 앞에서 정면을 보고 눈을 뜬 채 입을 편안하게 닫습니다.
2. 정상 자세가 관측된 시간을 약 30초 모읍니다. 얼굴 누락, 눈 감김, 큰 입 벌림, 큰 고개 회전 동안은 수집 시간이 멈추므로 실제 대기 시간은 더 길 수 있습니다.
3. `NORMAL / WARNING / DANGER`는 각각 **정상 / 경고 / 위험**입니다. 캘리브레이션 중에는 졸음 상태 판정을 시작하지 않습니다.
4. 화면에 양쪽 EAR, 평균 EAR, MAR, Pitch/Yaw/Roll, 판정 근거와 지속 시간, FPS를 표시합니다.
5. `C`로 기준값을 다시 수집하고, `Q`·`Esc`·창 닫기로 종료합니다. 시작할 때마다 새 기준값을 생성합니다.

웹캠이 열리지 않으면 다른 앱에서 카메라를 사용 중인지와 Windows 카메라 접근 권한을 확인합니다. `config.json`의 `camera.index`를 1 또는 2로 바꿔 다른 장치를 선택할 수 있습니다. 자동 선택이 실패하면 `camera.backend`에 `msmf` 또는 `dshow`를 지정합니다.

MediaPipe의 Windows 네이티브 로더가 한글 경로에서 모델을 찾지 못하는 문제를 처리했습니다. 이 경우 번들 그래프를 Python으로 읽고 모델 파일만 영문 임시 폴더에서 로드합니다. 종료하면 임시 모델을 정리하며, 설치된 MediaPipe 파일을 수정하지 않습니다.

## 구현 순서와 역할

| 단계 | 파일 | 역할 |
| --- | --- | --- |
| 1 | `drowsiness/camera.py`, `face_mesh.py` | 웹캠 입력, 추적 모드 Face Mesh 468개 랜드마크 추출 |
| 2 | `drowsiness/metrics.py` | 양쪽 EAR, 평균 EAR, MAR와 시간 기반 평활화 |
| 3 | `drowsiness/head_pose.py` | 6개 얼굴 점과 고정 3D 모델을 이용한 PnP 각도 추정 |
| 4 | `drowsiness/calibration.py` | 정상 데이터 수집, MAD 이상값 제거, 개인 기준값 생성 |
| 5 | `drowsiness/detector.py` | 각 지표의 지속 시간과 복합 근거를 이용한 3단계 판정 |
| 6 | `drowsiness/alarm.py`, `display.py` | 비동기 경보, 영상 옆 지표 표시 |
| 연결 | `drowsiness/app.py`, `main.py` | 전체 흐름과 종료 시 자원 정리 |
| 설정 | `drowsiness/config.py` | PC/Pi 설정과 값 검증 |

`mediapipe_compat.py`는 Windows 한글 경로 호환을 담당합니다. 감지 로직은 웹캠이나 운영체제에 의존하지 않습니다.

## EAR·MAR·Head Pose

EAR은 6개 눈 점으로 계산합니다.

```text
EAR = (거리(p2,p6) + 거리(p3,p5)) / (2 × 거리(p1,p4))
왼쪽 눈:  33, 160, 158, 133, 153, 144
오른쪽 눈: 362, 385, 387, 263, 373, 380
```

두 눈 모두 개인 EAR 임계값 아래에 있어야 눈 감김 근거로 인정합니다. 한쪽 눈을 감는 동작으로 인한 오탐을 줄이기 위한 조건입니다.

MAR은 입 안쪽의 세 쌍 수직 거리 평균을 입 너비로 나눕니다.

```text
MAR = (거리(81,178) + 거리(13,14) + 거리(311,402)) / (3 × 거리(78,308))
```

두 지표 모두 실제 영상 픽셀 좌표로 계산합니다. MediaPipe의 정규화 x/y를 그대로 사용하면 영상의 종횡비가 거리 비율을 왜곡할 수 있습니다.

고개 각도는 코(1), 턱(152), 눈 바깥쪽(33,263), 입꼬리(61,291)를 고정된 3D 얼굴 모델과 대응시켜 `solvePnP`로 구합니다. `Rodrigues`와 `RQDecomp3x3` 결과를 도 단위 Pitch/Yaw/Roll로 사용합니다. 영상은 추정 후 화면 표시에서만 좌우 반전합니다. x는 오른쪽, y는 아래쪽, z는 카메라에서 멀어지는 축이며, 양의 각도는 각 축의 오른손 회전 방향입니다. 판정에서는 부호와 관계없이 개인 중립 각도와의 차이 크기를 사용합니다.

초점거리는 영상 너비, 주점은 영상 중심으로 근사하며 렌즈 왜곡은 0으로 둡니다. 따라서 표시 각도는 근사값입니다. 개인 중립 자세를 빼서 설치 각도의 영향을 줄이지만, 얼굴 모양과 렌즈에 따른 오차까지 없애지는 않습니다. 재투영 오차가 눈 너비의 15%를 넘거나 얼굴이 너무 작으면 측정값을 사용하지 않습니다.

## 캘리브레이션

- 수집 전 유효성 검사: 양쪽 EAR 0.12~0.50, MAR 0.30 이하, 각 고개 각도 절댓값 25° 이하를 기본 정상 후보로 사용합니다. 시작할 때 정상 상태라는 전제가 필요합니다.
- 평활화 전의 원본 지표를 모읍니다. 얼굴이 사라지거나 관측 간격이 0.5초를 넘으면 관측하지 못한 시간은 수집 시간으로 계산하지 않습니다.
- 각 지표의 중앙값과 MAD(중앙 절대 편차)를 구합니다. `1.4826 × MAD`를 강건한 표준편차 추정치로 사용하고, 중앙값에서 3.5배 이상 벗어난 샘플을 제거합니다. 거의 일정한 데이터에 대비해 최소 편차도 둡니다.
- 최소 100개 이상, 전체의 60% 이상 샘플과 목표 시간의 60% 이상 관측 시간이 이상값 제거 후 남아야 기준값을 만듭니다. 부족하면 수집을 다시 시작합니다.
- EAR 임계값: 정상 EAR 중앙값의 72%, 범위 0.06~0.35.
- MAR 임계값: 정상 MAR 중앙값 + `max(0.25, 정상 MAR 편차 × 5)`, 범위 0.35~1.20.
- 고개 임계값: 기본 Pitch 15° / Yaw 20° / Roll 18°와 정상 편차 × 4 중 큰 값. 상한은 각각 35° / 45° / 35°입니다.

이상값 제거는 간헐적인 깜빡임과 움직임의 영향을 줄이는 장치입니다. 수집 시간 내내 비정상 자세를 유지하면 정상 기준을 알아낼 수 없습니다. 기준이 부정확해 보이면 정면 자세로 `C`를 눌러 다시 수집합니다.

## 기본 판정 기준

모든 시간은 프레임 개수가 아닌 `time.monotonic()` 기준입니다. EMA 평활화도 실제 관측 간격을 사용합니다.

| 상태/동작 | 조건 |
| --- | --- |
| 정상 | 아래 경고·위험 근거가 없음 |
| 경고 | 두 눈 감김 0.8초 이상, 큰 입 벌림 1.5초 이상, 또는 중립 고개 각도 이탈 1.5초 이상 |
| 위험 | 두 눈 감김 2초 이상 |
| 위험 | Pitch 이탈 4초 이상 |
| 위험 | 눈 감김·하품·고개 이탈 중 2개 이상의 확인된 근거가 함께 1초 이상 지속 |
| 경보음 | 현재 위험 근거가 추가로 2초 이상 끊기지 않고 지속 |
| 회복 | 낮은 단계의 근거가 1초 이상 유지되면 화면 상태를 낮춤 |

눈 감김만 지속될 경우 대략 0.8초에 경고, 2초에 위험, 4초에 경보가 시작됩니다. 평활화와 관측 주기로 약간의 지연이 추가됩니다. 하품이나 Yaw 회전만으로는 위험 단계가 되지 않습니다. Pitch 조건은 고개 숙임·젖힘이 오래 지속되는 상황을 검출하는 휴리스틱입니다.

얼굴 추적이나 자세 계산이 실패하면 `WARNING / Tracking unavailable`을 표시합니다. 이 경고는 졸음 판정과 구분되는 측정 불가 표시이며, 졸음 누적 시간과 경보 조건을 초기화합니다. 회복을 기다리는 동안 화면이 잠시 위험 상태여도 현재 위험 근거가 사라지면 새 경보음을 중단합니다. 이미 재생 중인 짧은 음은 끝날 수 있습니다.

경보음은 별도 스레드에서 Windows `winsound.Beep`, Linux `sounddevice`로 재생합니다. 기본은 1800Hz, 0.3초 음, 1초 반복입니다. 오디오 출력이 실패하면 화면과 콘솔에 표시합니다. PC 볼륨·출력 장치와 Pi 스피커 연결은 실제 장치에서 확인해야 합니다.

기본값을 바꾸려면 설정 JSON에 해당 항목만 추가하면 됩니다. 예:

```json
{
  "detection": {
    "eye_warning_seconds": 0.8,
    "eye_danger_seconds": 2.0,
    "yawn_seconds": 1.5,
    "head_seconds": 1.5,
    "nod_danger_seconds": 4.0,
    "fusion_seconds": 1.0,
    "recovery_seconds": 1.0,
    "alarm_delay_seconds": 2.0
  }
}
```

모든 설정은 `drowsiness/config.py`에 정의되어 있습니다. 부분 설정은 기본값과 병합하며, 알 수 없는 키와 잘못된 값은 시작 시 거부합니다.

## Raspberry Pi 이식

Python 3.11을 제공하는 **64비트 Raspberry Pi OS 환경과 USB 웹캠**을 대상으로 합니다. MediaPipe 0.10.18은 Python 3.11 Windows x64 및 Linux ARM64 wheel을 제공합니다([PyPI 배포 파일](https://pypi.org/project/mediapipe/0.10.18/#files)). 같은 Face Mesh API를 사용하도록 버전을 고정했습니다. OpenCV는 MediaPipe가 요구하는 `opencv-contrib-python` 하나만 설치해 중복 설치를 피합니다.

Pi로 소스·설정·requirements를 복사하고 PC의 `.venv`는 복사하지 않습니다. Python 3.11과 그래픽 데스크톱이 있는 Pi에서:

```bash
sudo apt update
sudo apt install libgl1 libglib2.0-0 libportaudio2 python3-venv
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py --config config.pi.json
```

Pi 설정은 캡처 640×480, Face Mesh 입력 너비 320, 단일 얼굴 추적, iris refinement 비활성화, 랜드마크 점 그리기 비활성화, OpenCV 스레드 1개입니다. 추정된 좌표는 원래 영상 크기로 환산합니다. 프레임을 건너뛴 횟수로 FPS를 부풀리지 않습니다.

USB 웹캠은 `camera.py`의 V4L2 입력을 그대로 사용합니다. CSI 카메라의 Picamera2 입력과 GPIO 부저는 아직 구현하지 않았으며, 필요한 경우 `read() -> (BGR frame, monotonic timestamp)` / `close()`와 `Alarm` 인터페이스에 맞춰 교체하면 감지 로직을 유지할 수 있습니다.

## 검증과 성능 목표

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip check
```

자동 테스트는 EAR/MAR 계산, 알려진 3D 자세 복원, 30초 기준값 생성, 이상값 제거, 개인 기준값, 짧은 깜빡임·한쪽 눈 감김, 경고·위험·경보 지연, 복합 근거, 추적 중단·프레임 지연, 회복, 15/30 FPS에서 같은 판정, 비동기 경보 연결, 실제 Face Mesh 모델 로드와 임시 파일 정리를 확인합니다. 경보 테스트에서는 오디오 출력만 대체합니다.

현재 개발 환경에서 의존성 검사와 자동 테스트가 통과했습니다. 웹캠 0번을 열 수 없어 실제 얼굴 웹캠 입력과 실제 오디오 출력은 아직 검증하지 못했습니다. Raspberry Pi 실기에서도 아직 실행하지 않았습니다. **15 FPS 이상과 오탐률 10% 이하는 구현만으로 달성했다고 보장하지 않습니다.**

검증 절차:

1. PC에서 조명·거리·안경 조건을 달리하며 정면 자세로 캘리브레이션합니다. 짧은 깜빡임, 대화, 좌우 확인 동작을 정상 평가 자료에 포함합니다.
2. 의도적인 지속 눈 감김, 긴 입 벌림, 고개 숙임과 복합 동작으로 표의 단계 전환·경보 지연·회복을 확인합니다. 표정 동작만으로 실제 졸음의 정답을 확정할 수 없으므로 실제 졸음 성능 평가는 별도 정답 라벨이 필요합니다.
3. Pi에서 워밍업·캘리브레이션 후 최소 5분간 얼굴을 추적하며 화면 FPS를 측정합니다. FPS는 캡처·추론·지표 계산·렌더링·키 입력을 포함하는 완료 프레임 처리율이며 최근 최대 60프레임 평균입니다. `Face Mesh` 시간은 추출 단계만의 처리 시간입니다. 장치 모델, 냉각, 해상도, 조명과 함께 결과를 기록합니다.
4. **오탐률 = FP / (FP + TN)** 으로 측정합니다. 예를 들어 정상 정답 구간을 1초 단위로 나누고, 유효 추적 프레임의 과반이 경고/위험이면 FP로 세는 기준을 평가 전에 고정합니다. 경고와 위험의 오탐률도 별도로 보고합니다. 캘리브레이션 구간은 제외하고, 추적 불가 시간 비율은 따로 보고합니다. 졸음 구간 검출률도 함께 확인해 경보를 줄이는 것만으로 목표를 맞추지 않습니다.
5. 목표를 충족하지 않으면 Face Mesh 입력 해상도와 판정 시간·임계값을 조정하고, 조정에 사용하지 않은 다른 사람·다른 녹화 구간에서 다시 평가합니다. 실제 정답 데이터 없이 오탐률 수치를 제시하지 않습니다.

기술 근거: [MediaPipe Face Mesh 공식 문서](https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/face_mesh.md), [OpenCV PnP 문서](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html).
